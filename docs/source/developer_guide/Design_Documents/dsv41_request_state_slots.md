# DeepSeek V4.1 Flash 请求状态槽实验

| 布局 | 历史与状态的所有权 | 运行入口 |
| --- | --- | --- |
| 原生布局 | 历史、窗口和压缩器由原生 KV 分组与块管理器分配 | 默认 MRV2 |
| 分离布局（旧三池，PR #14） | 专用三池计划分别管理历史页、窗口槽和压缩器槽，Pull 交接带有专用状态协议 | 旧分支的显式开关 |
| 候选布局（本 PR） | 一个原生 BlockPool 管历史页。每条活跃请求另领一个窗口槽和一个压缩器槽，每个 worker 只分配并注册一块连续存储 | 本 PR 的 CPU 与 NPU 组件入口 |

本 PR 叠在 #17 上，复用已有固定环形窗口、执行工作区和验证工具。#17 的紧凑页布局与此候选有各自的所有权规则和存储方式。本 PR 的新增代码还没有接到正常的 MRV2 服务入口。

## 槽号、存储与清零

P 与 D 分别分配本地槽。历史组的块号随 token 增长，40 层窗口共用请求的窗口槽号，3 个压缩器状态共用压缩器槽号。每个 TP worker 拥有自己的物理字节。以本次 Flash BF16 缓存形状计，每增加一个历史块、窗口槽或压缩器槽，持久存储分别增加 369,280、5,242,880 和 393,216 字节。每组另外保留 0 号槽，实测分配器为整块存储预留一次 2 MiB 对齐空间。

计算视图只覆盖实际槽数。给原版 Pull 的注册视图使用历史组的首维长度，以保持原协议的地址步长计算。构建时逐层检查注册视图的末尾是否落在整块存储内。部分注册视图会覆盖下一层字节，调用方必须只发布实际持有的组内 ID。清零入口接受组号和新领取的 ID，仅清除本组各层实际拥有的行。服务接入需要把组号从调度端一直传到清零端。把同一个 ID 在所有层上清零会破坏其他请求。

请求退役后，未完成 READ 的凭据仍持有源资源。设备失联或 DMA 完成状态未知时，服务必须继续隔离受影响的槽。组件试验已覆盖一个 D rank 完成、另一个在成功读取第一个来源后主动中止的情况。真实设备失联后的服务级回收仍待验证。

## 已有证据

- CPU 回归比较有界计算视图独立推导的字节范围与原版 Pull 产生的实际地址，覆盖不同 P/D 槽号、TP4→TP2 选源、延迟回收以及按组清零。
- 在两台 A2 上，两个 D rank 各从四个 P rank 读回 24,760,064 字节。四条请求的窗口经真实 Triton 提交、跨机 READ、D 重建后，逐层匹配最近的 128 行。该试验使用可区分的合成张量。
- 在 N=130，单次暖 READ 由 11,617,536 降到 6,374,656 字节，耗时 P50 由 704.73 降到 451.55 µs。在 N=257，原布局和候选均读取 6,374,656 字节。对照必须将 D 的完整块表与去掉空页的待加载列表分别传给 Pull。
- 单卡按 8 个状态槽预留并实际分配缓存时，8 条 64 Ki-token 输入的缓存底层存储由 2,166.91 降到 1,493.23 MiB，一条 128-token 输入则由 14.71 增到 53.54 MiB。整模接纳数待测。
- 40 层窗口操作的独立测量中，单请求 decode 在 eager 下由 3.28 增到 6.73 ms。每步重建窗口的开销可能抵消只在交接时获得的收益。端到端 TTFT、TPOT、吞吐与容量需在完整服务上测量。

上述硬件记录来自组件原型。PR 中整理后的组件和新增按组清零需在最终服务版本再次上卡验证。

## 复现

在配置了匹配版本 vLLM 与 vllm-ascend 的源码仓库根目录运行 CPU 测试。

```sh
pytest -q tests/ut/core/test_dsv41_request_state_storage.py tests/ut/core/test_dsv41_native_read_bytes.py
```

NPU 探针入口为 `python -m tests.e2e.deepseek_v41.probe_request_state_pull ROLE RANK --ip LOCAL_IP --exchange DIR`。两端在同一次实验中并发运行，P 启动 rank 0 到 3，D 启动 rank 0 到 1。两侧分别配置只含各自设备的可见列表，并使用新的空交换目录。使用两端共享目录或显式转交握手与回执文件。加 `--partial` 可复测部分 TP 完成后的隔离。握手文件包含当次进程会话和设备地址，仅在本次运行有效。

## 整模验收

1. 在正常 MRV2 服务中绑定分组容量、槽号发布、计算和注册视图、按组清零与带完成事件的回收。分别记录候选在混部及 P/D 两侧实际启用的证据。
2. 同一 W4A8 权重、冻结环境、TP 与相同输入下，先测 N=130 连续 130 输出，再测 128、129、257。比较独立参考与实际 P 源、D 加载，逐步比较相同前缀的分布。低置信输入进行同副本重复，并记录高置信文本。
3. 正确性通过后，在干净服务上用官方代理和 `vllm bench serve` 运行每轮至少 100 个请求的对照。混部与 P/D 各自比较三种布局，记录 HBM、实际并发、排队、传输、TTFT、TPOT、吞吐与错误数。
