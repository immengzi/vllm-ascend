# DeepSeek V4.1 Flash 的统一 128 KiB KV 布局

这项设计把历史、滑动窗口（SWA）和压缩器状态的生命周期分开管理。每个 TP worker 分配一块连续的 KV 存储，每个 DP 副本的调度器用同一个原生 BlockPool 发放页号。所有层视图沿页号维的步长都是 131,072 字节。一个页号在任一时刻只归一个缓存组。

## 同一个页号可以存什么

下表按一个 worker 计算。历史按 128 个原始 token 位置计一块，每块由三个历史组分别申请一个独立页号。例如调度器可以给它们页号 17、31 和 42。

| 谁申请 | 一个页号里的内容 | 有效大小 | 页内空余 |
| --- | --- | ---: | ---: |
| 历史组 A | 一层未压缩的 BF16 历史 KV | 128 KiB | 0 |
| 历史组 B | 两层二倍压缩的历史 KV，各 64 KiB | 128 KiB | 0 |
| 历史组 C | 另一层压缩 KV 64 KiB，四层索引及 scale 共 40.625 KiB | 104.625 KiB | 23.375 KiB |
| 任一 SWA 层 | 一条请求在本层的 128 行 BF16 环形窗口 | 128 KiB | 0 |
| 任一压缩器层 | 一条请求在本层的 32 行 FP32 状态 | 128 KiB | 0 |

因此，一块完整历史实际占 384 KiB。窗口和压缩器按请求分配，一条请求分别使用 40 页和 3 页，持久状态共 5.375 MiB。比如页号 17 归还后再分给某个 SWA 层，同一地址的整个 128 KiB 就用来存那一层窗口。窗口写到第 129 行时绕回第 1 行，历史仍按块追加。

## 预算和接纳如何对应

设 S、C 分别为窗口槽和压缩器槽的配置数量，一个槽覆盖一条请求的所有同类层。设 G 为从 worker 可用 KV 字节预算按 128 KiB 向下取整得到的页数。启动时建立一个大小为 G × 128 KiB 的 KV 张量，使用 Mooncake 的对齐分配和注意力工作区还会产生额外开销。

| 用途 | 逻辑容量 |
| --- | ---: |
| 原生 null 页 | 1 页 |
| 40 个窗口组 | 40 × S 页 |
| 3 个压缩器组 | 3 × C 页 |
| 可以同时驻留的历史块总数 | ⌊(G − 1 − 40S − 3C) / 3⌋ |

以 G=108、S=2、C=3 为例，扣除 1 个 null 页、80 个窗口页和 9 个压缩器页，剩余 18 页正好能装 6 块历史。两条各需 3 块历史的请求可以用完这 6 块。此时压缩器还有一个槽，第三条请求仍会因窗口和历史的上限而排队。减少配置槽数可在下次启动时让出历史容量；运行中保留这些配额以保障状态接纳。

各组先检查同一请求的需求，通过后才由原生管理器分配页号。延迟释放的页继续占用该组配额，直到原生持有者释放引用。跨端在途传输的完成与错误处理沿用 connector 的生命周期。

## 混部与 P/D 的执行

混部时，同一请求一直持有各层的环形状态。算注意力前，worker 把最多 127 行旧窗口与本步的新行按时间顺序放进同一份临时工作区，计算后再把最新行写回环中。40 层复用该工作区。持久页节省的空间可能提高压力负载下的接纳量；逐步整理窗口会增加计算和带宽开销。实际影响需要同时看排队、吞吐和逐 token 延迟。

P/D 分离时，两端应显式选择相同布局。以 N 个输入 token 为例，P 提供前 N−1 个位置的历史、索引、窗口和压缩器状态，D 分配自己的目标页，再算最后一个输入 token。P 的页 17 可以对应 D 的页 53。每个分量的地址由其已注册的基址、所在端的页号、统一步长决定，层内偏移已计入视图基址。原版 Mooncake Pull 消费各组的页号和张量视图，传输长度按分量有效数据计算。两端可分别配置容量。部署时需核对两端的布局和层规格。

## 启用与验证

在 Ascend 的 `--additional-config` 设置 `{"enable_deepseek_v41_logical_state_pools": true}`。默认使用原始布局。`deepseek_v41_swa_slots` 和 `deepseek_v41_compressor_slots` 各自接受一个正整数，默认取本端的 `max_num_seqs`。

当前支持 MRV2、BF16 历史和窗口、INT8 索引及 FP16 scale，以及对应的 Flash 压缩器。要求静态放置、启用 hybrid KV 管理、PP=PCP=DCP=1。关闭前缀缓存、SWA bounded replay、推测解码、KVPP、可扩展 KV 缓存和微批前向重叠。分离部署使用 MooncakePullConnector。

CPU 单测覆盖实际 storage、页步长、槽数对容量的影响、接纳失败的原子性、延迟释放和窗口边界。整模概率、真实 SDK READ、设备流完成时序和长短负载下的性能需要在目标 NPU 上验收。
